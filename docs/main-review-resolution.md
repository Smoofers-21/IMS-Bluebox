## Adopted changes

| Finding | Decision and resulting behavior |
| --- | --- |
| A2 — static caching | Correct content-hash URLs generated by `asp-append-version` receive one-year immutable caching. Bare, incorrect, or duplicate version parameters receive one hour. Security headers remain present; dynamic pages/errors remain `no-store`. Checking the hash avoids keeping an old unversioned file for a year. |
| B1 — login rate limit | Built-in fixed-window limiter permits 10 POSTs per minute per client address per instance, with no queue. Further POSTs return 429 and retry guidance. GETs are unlimited, so loading the form does not consume attempts. The app does not trust arbitrary forwarded-address headers. |
| B2 — username timing | Missing usernames still verify the supplied password against a process-wide dummy hash and always fail. This removes the skipped-hash fast path; database/cache differences and legacy hashes mean this is not a constant-time guarantee. |
| B3 — headers/cookies | Session cookies require HTTPS. `X-XSS-Protection` is `0`; the existing CSP remains. Added same-origin referrer policy and disabled camera/microphone/geolocation permissions. Poster images retain their explicit no-referrer policy. |
| C1 — capped lists | Catalog, Inventory, and Manage Catalog use 100-row pages with one-row lookahead. Previous/Next preserve search/type/warehouse filters as applicable. New filter submissions start at page 1. Manager edit links and save redirects preserve the list page/search; invalid posts reload the same page. Stable tie-breakers and bigint offsets avoid duplicates from tied sort keys and arithmetic overflow. |
| C2 — error handler | Error pages link to `/` (the overview landing flow). SQL exceptions/timeouts return 503; unexpected errors and direct `/Error` requests return 500. Both messages are generic; details stay in server logs, and error rendering does not require database cookie validation. |
| D1 — AllowedHosts | Development documentation explains private hostname/IP overrides for class demos and later hosting, distinct from listener/firewall/certificate setup. |
| D2 — reproducible SQL CI | SQL Server 2022 CU28 on Ubuntu 22.04 uses the specific `2022-CU28-ubuntu-22.04` tag. The original digest pin failed Docker resolution and was removed after PR #6 review; an HTTP registry response alone did not verify that Docker could pull it. Future upgrades require a deliberate workflow change and the full disposable SQL suite. No teacher credentials are used. |
| E — documentation | Removed obsolete future-merge instructions for PR #5 from active guides. The project plan and Word copy, requirements, setup, architecture, SQL catalog, and validation record reflect the follow-up. Historical counts stay tied to their actual commits/runs. |

## Suggestions deferred or retained

| Finding | Reason |
| --- | --- |
| A1 — sort by ID | Retain `transaction_datetime DESC, transaction_id DESC`. Identity allocation is not a timestamp or commit-order guarantee under concurrent transactions, clock changes, or historical imports. Using ID alone would change the documented chronological view. A supporting timestamp index would be a separate DDL decision. |
| A3 — foreign-key indexes | Excluded: indexes are DDL changes. No new migration, index, constraint, column, collation, or database option is included. |
| A4 — blanket RECOMPILE | No measured plan problem on the class dataset; recompiling every filtered request adds CPU and changes plan caching. Revisit with representative execution plans rather than applying a blanket hint. |
| A5 — teacher server version | No teacher-server query is run from this workspace. The Windows setup checklist asks for version verification (SQL Server 2014 or newer for pooled isolation-reset behavior). Overview already explicitly sets READ COMMITTED; serializable stock writes remain unchanged. An older target needs a separate compatibility review. |
| B4 — image CSP | Retain manual HTTPS poster URLs for movies and games, with manager-only saves and no server fetch of arbitrary poster URLs. A movie-CDN-only allowlist would exclude agreed game posters. |
| C3 — VARCHAR encoding validation | No assumed ASCII/Windows-1252 rule. Accurate rejection must follow each column's actual collation/code page, including UTF-8 installations; that metadata has not been verified on the teacher server. Existing length validation remains, and the documented non-Unicode storage limitation remains. Avoid unsupported characters in the class demo; robust Unicode storage is a separate database decision. |
| C4 — duplicate warning | Optional convenience feature beyond this focused review. Separate format editions remain supported; no new uniqueness rule is introduced. |
| E — cosmetic abstractions/query merging | Actor-ID parsing, poster-helper cleanup, and employee-query combining have no demonstrated correctness/performance benefit here. Existing transaction locks and last-manager protection remain intact. |
